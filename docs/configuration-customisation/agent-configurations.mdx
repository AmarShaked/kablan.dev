title: "Agent Profiles & Configuration"
description: "Configure and customise coding agent variants with different settings for planning, models, and sandbox permissions"

Agent profiles let you define multiple named variants for each supported coding agent. Variants capture configuration differences like planning mode, model choice, and sandbox permissions that you can quickly select when creating attempts.

<Info>
Agent profiles are used throughout Kablan wherever agents run: onboarding, default settings, attempt creation, and follow-ups.
</Info>

## Common Use Cases

| Use case | Configuration |
|----------|---------------|
| **Fast iteration** | Disable planning mode, use a faster model |
| **Complex tasks** | Enable planning mode, use a more capable model |
| **Autonomous work** | Skip permission prompts (use with caution) |
| **Code review** | Require approvals for all changes |
| **Multi-instance** | Enable Claude Code Router for parallel work |

## Key Concepts

<AccordionGroup>
<Accordion title="Planning Mode">
The agent writes a plan before it writes code, and waits for you to approve the approach. Worth the extra step on complex work; overhead on a one-line change.
</Accordion>

<Accordion title="Permission Prompts">
Agents ask before destructive actions — deleting files, running shell commands, changing system configuration. Setting `dangerously_skip_permissions` lets the agent run unattended and removes that guardrail.
</Accordion>

<Accordion title="Claude Code Router">
Distributes requests across several Claude Code instances running in parallel. Useful when you have multiple tasks in flight at once.
</Accordion>

<Accordion title="Sandbox Modes (Codex)">
Controls what the agent can reach:
- **read-only** — can read files, cannot modify
- **workspace-write** — can modify files inside the project directory
- **danger-full-access** — unrestricted filesystem access
</Accordion>

<Accordion title="Approval Levels">
Determines when the agent stops to ask:
- **untrusted** — before every action
- **on-failure** — only when something goes wrong
- **on-request** — only when explicitly asked
- **never** — fully autonomous
</Accordion>

<Accordion title="Reasoning Effort">
How much the model thinks before answering. Higher is more thorough but slower and more expensive; lower is faster but can miss nuance.
</Accordion>
</AccordionGroup>

## Managing Configurations

In the Settings dialog (`G` then `S`), the **Agents** section lists agents on the left and that agent's configurations on the right.

<Frame>
<img src="/images/settings-beta-agents.png" alt="The Agents section of Settings, showing the Agent and Configuration columns and the options form below" />
</Frame>

### Creating a configuration

1. Click **+** in the Configuration column.
2. Give it a name, e.g. `PRODUCTION`.
3. Either clone an existing configuration or start blank.
4. Click **Create Configuration**.

### Editing a configuration

Select the agent, select the configuration, edit the form below, then save.

### Deleting a configuration

Select it, click delete, and confirm.

<Warning>
You cannot delete an agent's only configuration — each agent keeps at least one.
</Warning>

### Setting the default

Click the **Default** badge next to a configuration. The default is pre-selected in the agent dropdown when you create a new attempt, and is used for follow-up messages.

## Configuration Structure

The profiles configuration uses a JSON structure with an `executors` object containing agent variants:

```json profiles.json
{
  "executors": {
    "CLAUDE_CODE": {
      "DEFAULT": { "CLAUDE_CODE": { "dangerously_skip_permissions": true } },
      "PLAN":    { "CLAUDE_CODE": { "plan": true } },
      "ROUTER":  { "CLAUDE_CODE": { "claude_code_router": true, "dangerously_skip_permissions": true } }
    },
    "GEMINI": {
      "DEFAULT": { "GEMINI": { "model": "default", "yolo": true } },
      "FLASH":   { "GEMINI": { "model": "flash",   "yolo": true } }
    },
    "CODEX": {
      "DEFAULT": { "CODEX": { "sandbox": "danger-full-access" } },
      "HIGH":    { "CODEX": { "sandbox": "danger-full-access", "model_reasoning_effort": "high" } }
    }
  }
}
```

<AccordionGroup>
<Accordion title="Structure Rules">
  - **Variant names**: Case-insensitive and normalised to SCREAMING_SNAKE_CASE
  - **DEFAULT variant**: Reserved and always present for each agent
  - **Custom variants**: Add new variants like `PLAN`, `FLASH`, `HIGH` as needed
  - **Built-in protection**: Cannot remove built-in executors, but can override values
</Accordion>

<Accordion title="Configuration Inheritance">
  - Your custom settings override built-in defaults
  - Built-in configurations remain available as fallbacks
  - Each variant contains a complete configuration object for its agent
</Accordion>
</AccordionGroup>

### Universal Options

These options work across multiple agent types:

<ParamField path="append_prompt" type="string | null">
Text appended to the system prompt
</ParamField>

<ParamField path="base_command_override" type="string | null">
Override the underlying CLI command
</ParamField>

<ParamField path="additional_params" type="string[] | null">
Additional CLI arguments to pass
</ParamField>

<Warning>
Options prefixed with "dangerously_" bypass safety confirmations and can perform destructive actions. Use with extreme caution.
</Warning>
