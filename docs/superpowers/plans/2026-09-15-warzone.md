# Warzone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/warzone` page: fixed 16-slot ring of eligible task chats, centre focus for full chat + reply (and create-from-empty), global + project filter, priority overflow.

**Architecture:** Pure slot/eligibility helpers + a new page that fans out `useAllTasks` (same as All Tasks). Ring tiles render a compact live peek from task turn fields (updated via existing live invalidation). Centre reuses `TaskRunPanel` / conversation + follow-up, chat-only. Create mode reuses create-and-start without navigating away from Warzone.

**Tech Stack:** React, React Router, TanStack Query, Vitest, existing Kablan conversation providers.

**Spec:** `docs/superpowers/specs/2026-09-15-warzone-design.md`

## Global Constraints

- Stay on `/warzone` when focusing or creating (do not navigate to `paths.task`).
- Centre is chat-only: no Diffs / Details panels.
- Fixed 16 slots; do not reshuffle when tasks leave eligibility.
- Eligibility: running OR needs-you OR `status === 'inreview'`.
- Overflow: priority fill + “+N more”; no second page.
- Tiles are read-only (no composer).
- No new backend routes or `shared/types.ts` edits for v1.
- Do **not** git commit unless the user explicitly asks.
- Follow existing frontend style (Prettier, single quotes, 80 cols where practical).

```ts
import type { TaskWithAttemptStatus } from 'shared/types';
import { taskNeedsAttention } from '@/utils/taskActivity';

export function isWarzoneEligible(task: TaskWithAttemptStatus): boolean {
  if (task.has_in_progress_attempt) return true;
  if (taskNeedsAttention(task)) return true;
  if (task.status === 'inreview') return true;
  return false;
}

/** Lower number = higher priority for ring fill. */
export function warzonePriority(task: TaskWithAttemptStatus): number {
  if (task.has_unseen_turns && !task.has_in_progress_attempt) return 0;
  if (task.last_attempt_failed && !task.has_in_progress_attempt) return 1;
  if (task.has_in_progress_attempt) return 2;
  return 3; // inreview (and any other eligible)
}

export function sortWarzoneTasks<T extends TaskWithAttemptStatus>(
  tasks: T[]
): T[] {
  return [...tasks].sort((a, b) => {
    const pd = warzonePriority(a) - warzonePriority(b);
    if (pd !== 0) return pd;
    return new Date(b.updated_at).getTime() - new Date(a.updated_at).getTime();
  });
}
```

### Task 2: Slot geometry + stable assignment

**Files:**
- Create: `frontend/src/lib/warzone/slots.ts`
- Create: `frontend/src/lib/warzone/slots.test.ts`

**Interfaces:**
- Consumes: `sortWarzoneTasks` from Task 1
- Produces:
  - `WARZONE_SLOT_COUNT = 16`
  - `warzoneSlotCells(): { slot: number; row: number; col: number }[]` — slots 1–16 with 1-based CSS grid row/col (centre 2–4,2–4 empty of slots)
  - `assignStableSlots(args: { eligibleIds: string[]; previous: Map<number, string>; reserved?: { slot: number; taskId: string } | null }): { assignment: Map<number, string>; overflow: number }`
    - Keep previous assignments if id still eligible
    - Drop ids no longer eligible
    - Apply `reserved` if provided (create-from-empty)
    - Fill remaining empty slots (lowest slot number first) from `eligibleIds` order (already priority-sorted), skipping ids already assigned
    - Cap at 16; `overflow = max(0, eligibleIds.length - assignedCount)` using total eligible length vs unique assigned

Clockwise order for slot numbers (tring-style), 1-based grid coords:

| slot | row | col |
|------|-----|-----|
| 1–5 | 1 | 1–5 |
| 6 | 2 | 5 |
| 7 | 3 | 5 |
| 8 | 4 | 5 |
| 9–13 | 5 | 5–1 (9 at col5 … 13 at col1) |
| 14 | 4 | 1 |
| 15 | 3 | 1 |
| 16 | 2 | 1 |

  - `assignStableSlots`: first fill takes slots 1..n in order of eligibleIds
  - removing an id frees its slot; others stay
  - new id takes lowest empty slot
